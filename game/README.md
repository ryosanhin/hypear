# ゲーム進行と流れの更新

`GameSession` が開始・終了、入力、得点とコンポーネント間の接続を担当する。
通常の `_process(delta)` から各流れへゲーム内経過時間を渡す。

| 周期の所有者 | 開始 | 更新対象 | 終了 |
| --- | --- | --- | --- |
| `FruitFlow` の `DiscreteStepper` | `start_game()` | 全果実の供給と `MainConveyor` の搬送 | 供給失敗で停止、再開始でゼロから作成 |
| `ShippingConveyor` 内の出荷ごとの `Shipment` | `ship()` で左右を同時出荷した時点 | その二箱の下向き移動とパス上の搬送 | 両箱の搬送完了で除去、ゲーム終了で停止 |

更新間隔は `DemoSettings.flow_tick_interval`（初期値0.1ゲーム内秒）。
果実はゲーム開始を起点に、出荷した箱はその出荷を起点に更新する。
新たな出荷やパスへの乗り換えは、既存の周期をリセットしない。
間隔は果実ではゲーム開始時、箱では出荷時に読み込む。

`DiscreteStepper` は各流れの時間を蓄積し、長いフレームでは必要な回数を
固定量ずつ処理して端数を持ち越す。更新の間に位置の補間は行わない。
速度は「距離 / ゲーム内秒」、供給は `supply_interval` の秒数で扱うため、
更新間隔を変えても1秒あたりの搬送距離と供給頻度は変わらない。

果実は各更新の内部で **次の供給時刻まで搬送 → 供給・入口の詰まり判定 →
残り時間の搬送** の順に処理する。供給間隔と更新間隔が割り切れない場合や、
一更新内に複数の供給がある場合も、生成から搬送に使う時間を維持する。
自動供給の表示も共通周期の更新時に反映される。開始直後の即時供給は行わない。

箱の下向き移動は `BoxView.advance_ship_entry()` が距離から所要時間を計算する。
Tweenは使用せず、到達に使わなかった時間だけを `ShippingConveyor` が
パス移動へ渡す。例えば0.1秒の更新中0.04秒で到達した場合は、残り0.06秒を
パス移動に使う。左右の乗せ位置や移動距離が異なっても周期は共有する。

仕分けと出荷は `_unhandled_input()` からその場で実行する。
更新境界を待つのは搬送と自動供給であり、入力や新しい空箱の生成は待たせない。
`Engine.time_scale` が適用済みの `delta` をそのまま利用するため、早送り時に
アプリ側で倍率を掛ける必要はない。

供給失敗でゲームが終了すると、果実と全出荷を停止し、蓄積時間を破棄する。
再開始時は果実、搬送途中の箱、未出荷の旧箱、状態との接続を除去して作り直す。
出荷箱には独自の `_process()` やTweenを持たせず、更新入口はセッションに集約する。
ステージを解放すると、セッション配下の表示と周期も破棄される。
