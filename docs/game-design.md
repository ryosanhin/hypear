# hypear ゲーム仕様と開発再開ガイド

## ゲームの狙い

`hypear` は『ウマ娘』に着想を得た非公式ファン制作のミニゲーム。フリオーソが選果場で梨を受け取り、左右の箱に振り分けて出荷する。梨の見た目から重量を見積もりながら、コンベアが詰まる前に目標得点へ到達する。

梨ごとに決まった投入先はない。各箱を目標重量へ近づけると基礎点が上がり、左右の重量も近ければ均等ボーナスが付く。片箱だけで早めに得点を確保するか、果実を待って両箱の高得点を狙うかを、そのときの箱の重さとコンベアの混み具合で決める。

初期企画では「箱ごとに目標重量へ寄せる方式」と「左右の重量差で採点する方式」を検討していた。現行版は前者を基礎点、後者をボーナスに採用している。梨はコンベア上で順に待機し、投入した果実は箱の累積重量に加算される。

## プレイの流れ

| 場面 | 動作・表示 |
| --- | --- |
| タイトル | 「スタート」でゲームへ。「権利表記」でビューアを開き、パネル外で左クリックを離すと閉じる。背景の梨はタイトル専用の演出。 |
| 開始準備 | ロード用シャッターで画面を覆い、ステージをロードする。空箱、重量計、得点 `0/600点`、果実数 `0/10` はシャッターが開く前に準備する。 |
| プレイ開始 | シャッターが開き切ってから時間計測と供給を開始する。最初の梨は供給間隔が経過してから搬入される。 |
| 仕分け | ← で左箱、→ で右箱に、終端に到着した最も古い果実を 1 個入れる。到着前の果実は取り出せない。キーの長押しによるリピート入力は無視する。 |
| 出荷 | ↓ で左右を同時に出荷。片側だけに梨が入っていても出荷できる。両箱が空ならそのまま続行する。出荷は押した時点で採点し、すぐに左右の新しい空箱を用意する。 |
| クリア | 出荷で累計が 600 点以上になると終了。結果シャッターに経過時間を小数第 2 位まで表示する。 |
| ゲームオーバー | 次の果実を受け入れられなかった時点で終了。結果シャッターに確定した累計得点を表示する。 |
| タイトルへ戻る | 結果シャッターが閉じ切った後に「タイトルへ戻る」が有効になる。再スタートすると新しいステージで得点・経過時間・果実数がゼロから始まる。 |

果実数カウンターは、搬送中と終端で仕分け待ちの未処理果実を合計する。果実が手元に表示されてもカウントは維持し、箱へ入れたときに 1 減る。容量に達した瞬間は続行できる。次の供給時に容量いっぱい、または容量に余裕があっても入口に必要な間隔がなければゲームオーバーになる。箱の重量超過は採点に反映される。

操作の定義は [`project.godot`](../project.godot)、ステージ入力の受け付けは [`GameSession._unhandled_input()`](../game/stage/game_session.gd)、開始・復帰ボタンの接続は [`title.gd`](../game/title/title.gd) と [`result_shutter.gd`](../game/shutters/result_shutter.gd) にある。

| 項目 | 現行値 | 変更箇所 |
| --- | --- | --- |

設定を変えるときはスクリプトの既定値と `.tres` の上書きを合わせて確認する。供給間隔を短くする場合は、搬送速度と果実間隔も見て、入口の詰まり方が意図した難易度になるか試す。

## 採点

出荷得点は **左箱の基礎点 ＋ 右箱の基礎点 ＋ 均等ボーナス**。箱の採点は、出荷する箱の重量を目標重量で割った充填率 `r` に基づく。

| 充填率 | 箱 1 個の基礎点 |
| --- | --- |
| 50% 未満 | 0 点 |
| 50% 以上、80% 未満 | `round(100 × (r − 0.5))` |
| 80% 以上、100% 以下 | `t = (r − 0.8) / 0.2` として `round(30 + 20 × t + 50 × t²)`。目標ちょうどで 100 点。 |
| 100% 超 | `u = max(0, 1 − (r − 1) / 0.15)` として `round(100 × u⁴)`。目標超過で急減し、115% 以上で 0 点。 |

均等ボーナスは `d = |左の重量 − 右の重量| / 目標重量`、`c = max(0, 1 − d / 0.3)` として、`round(0.6 × 左右の低い方の基礎点 × c²)`。重量差が目標の 30% 以上か、どちらかの基礎点が 0 点ならボーナスは 0 点。左右がともに目標重量なら最大の 260 点になる。

| 左／右の重量（目標 20） | 左／右の基礎点 | ボーナス | 出荷得点 |
| --- | --- | --- | --- |
| 20／20 | 100／100 | 60 | 260 |
| 20／19 | 100／73 | 30 | 203 |
| 20／21 | 100／20 | 8 | 128 |
| 20／0 | 100／0 | 0 | 100 |

中身がある箱の上には、その箱の基礎点が `+N` と表示される。均等ボーナスが正のときは画面中央付近に `ボーナス +N` が出る。累計 HUD には合算後の得点とクリア目標を表示する。採点を変更したら、実ゲームの [`ScoreCalculator`](../game/stage/score_calculator.gd)、同じ式を持つ [採点シミュレーター](hypear-score-simulator-simple.html)、[ステージテスト](../tests/stage/stage_test.gd) の期待値を合わせて確認する。

## 実装の入口

| 調べたいこと | 入口と責務 |
| --- | --- |
| 起動、結果、タイトル復帰 | [`game_loop.tscn`](../game/game_loop.tscn) と [`game_loop.gd`](../game/game_loop.gd)。`GameLoop` がタイトルの開始要求と `GameSession.game_finished` を受け取り、[`SceneController`](../utils/scene_management/README.md) に画面切り替えを依頼する。ロード用シャッターとクリア・ゲームオーバー用シャッターは [`game/shutters/`](../game/shutters/) にある。 |
| ゲーム状態とコンポーネントの接続 | [`stage.tscn`](../game/stage/stage.tscn) と [`GameSession`](../game/stage/game_session.gd)。ステージ直下の各ノードをエクスポート参照でつなぎ、準備、プレイ中、クリア、ゲームオーバーを管理する。終了確定時に状態・得点・経過秒数を一度通知し、以降の時間更新とプレイ操作を止める。 |
| 果実の供給と手元への表示 | [`FruitGenerator`](../game/stage/cargo_item/fruit_generator.gd) が重量を抽選し、[`MainConveyor`](../game/stage/conveyors/main_conveyor.gd) が `Path2D` 上で供給順に搬送する。終端到着を受けた `GameSession` が [`SortingCharacter`](../game/stage/character/character.gd) に表示を渡してベルト上の同じ果実を隠す。 |
| 箱の重量・投入・搬送 | [`BoxState`](../game/stage/boxes/box_state.gd) が累積重量と通知を持ち、箱の絵と重量計が変化を受け取る。`GameSession` が出荷を判断し、[`BoxesViewController`](../game/stage/boxes/boxes_view_controller.gd) が箱を蓋閉め・移動演出へ渡す。ベルト到着後は [`ShippingConveyor`](../game/stage/conveyors/shipping_conveyor.gd) が終端まで運んで解放する。親の切り替えと描画順は [箱表示の README](../game/stage/boxes/README.md) を参照する。 |
| 得点の見え方と描画順 | [`stage.tscn`](../game/stage/stage.tscn) の `ScoreEffects` は箱ごとの `GainScore` の追加先であり、中央に出す `BonusScoreSpawner` も持つ。果実数カウンターはステージ直下、累計得点は `CanvasLayer`、結果シャッターは `ResultLayer` にある。配置変更時は、それぞれが果実・箱・シャッターに対してどの順で重なるかを実画面で確認する。 |

`GameSession.advance(delta)` はプレイ中のフレーム経過時間を供給時刻で区切り、果実と出荷ベルト上の箱を進める。箱がベルトへ乗るまでの移動、投入ポーズ、得点表示は、各表示の Tween や Timer で進む。搬送のコマ送りや早送りを再検討する場合は、時間の制御対象にどの演出を含めるかを [Issue #4](https://github.com/ryosanhin/hypear/issues/4) と現行コードで確認する。

## 再開時の動作確認

1. Godot 4.7 系でリポジトリを開く。CI の指定は 4.7.1。基準ビューポートは 960×720（4:3）、レンダラーは GL Compatibility、ストレッチモードは `canvas_items`。[`project.godot`](../project.godot) と [CI 定義](../.github/workflows/cli_test.yml) を参照する。
2. [README のセットアップ手順](../README.md#font) に沿って、DotGothic16 の実ファイルを `third_party/fonts/DotGothic16-Regular.ttf` に置いてからインポートする。共有テーマがこのパスを参照する。確認時点の CI は成功表示だったが、実行ログにはフォントとテーマの読み込みエラーが残っていた。ログも確認する。[該当する CI 実行](https://github.com/ryosanhin/hypear/actions/runs/44750514804)
3. [テスト手順](../tests/README.md) のヘッドレステストで、投入順、採点、箱の交換、クリア、容量超過と入口詰まりによる終了を確認する。実ステージを使うが、テスト用の重量・供給設定に置き換えて時間を手動で進める。
4. プロジェクトのメインシーンから起動し、クリアとゲームオーバーの両方でタイトルへ戻って再スタートする。シャッターが開く前の空箱・HUD、手元の梨とベルト上の表示、片箱だけの出荷、両箱出荷時のボーナス、連続出荷時の重なり順を目視する。詳細は [デバッグプレイの項目](../tests/README.md#デバッグプレイ) を参照する。
5. Web 版を確認する場合は、使用する Godot に対応したエクスポートテンプレートを入れ、[Web プリセット](../export_presets.cfg) で書き出す。ブラウザー上でゲーム操作に加えてタイトルの権利表記を開く。ビューアは `game/title/license_viewer/texts/*.txt` を実行時に読むため、エクスポートの同梱フィルターも確認する。素材の扱いは [README のライセンス概要](../README.md#license) と [ウマ娘素材のライセンス](../UMAMUSUME_ASSETS_LICENSE.md) を参照する。

## 仕様を変えるときに残すこと

- 供給間隔・目標得点・採点式などを調整したら、何を狙った変更かを関連 Issue や PR に残す。特に「箱の重量を考える余裕」と「コンベアを詰まらせない忙しさ」のどちらを変えたいかが分かると、再調整しやすい。
- 現行のゲームは効果音・BGMなし。音を追加する場合は、投入・通常出荷・均等ボーナス・終了など、音で伝えたい出来事と素材の扱いを決める。
- 公開版を後から更新する場合は、配布先と使用したコミットまたはタグを残しておくと、手元の `main` と配布版の挙動を照合しやすい。

ルートの `AGENTS.md` からは、この文書、README のセットアップ、テスト手順、コーディング・PR 規則へリンクする。ゲームの数値や採点式を変更したら、この文書の該当箇所をコードと一緒に更新する。
